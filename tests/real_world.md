# ZXL-E real-world artifact bench (2026-05-05)

First measurement of zxle on artifacts not generated by `tests/make_fixtures.sh`. Eight artifacts pulled from upstream sources, packed/unpacked, measured against `xz -9e` and `zstd -19 --long=27`. All round-trips byte-exact.

Two passes are reported below: (1) the initial run on the post-M3h binary, which surfaced the small-tarball regression, and (2) the rerun after the **min-pack fallthrough** fix (pack twice — once with container unwrap engaged, once forced-opaque — keep the smaller).

Reproduce: `bash tests/real_world/bench_one.sh <file>` after dropping the artifacts into `tests/real_world/`. Source URLs below.

## Routing summary

- **leftpad.tgz / is-odd.tgz** — `gz: mode=1 (preflate) inner=tar` then `tar: 5 regular (5 store)` / `tar: 4 regular (4 store)`. Unwrap engaged fully; payload (mostly tiny JS text) fed into solid.
- **which.pkg.tar.zst** — KIND_OPAQUE. The zstd ladder's 7 `(level, --long)` probes do not reproduce makepkg's output byte-exact (see "Concrete misses" below).
- **hello.deb** — `ar: 3 entries (3 store, 0 gzip-store, 0 bz2-store, 0 png-store, 0 jpeg-store)`. The ar walker parsed the archive but every inner entry (`debian-binary`, `control.tar.xz`, `data.tar.xz`) routed through OP_STORE because no `OP_XZ_STORE` exists yet. Confirms the modern-deb prediction.
- **release.zip** — `zip: 20 entries (9 redeflate, 3 preflate, 0 store-orig, 8 stored, 0 jpeg-store, 0 png-store)`. M2/M3a path engaged on 12 of 20 entries. The 8 stored entries (likely already-compressed payloads) and small total size cap the headline at near-tie.
- **hello.tar.gz / make.tar.gz** — `gz: mode=1 (preflate) inner=tar` then `tar: N regular (N store, ...)`. xz-9e cannot crack the gzip body; zxle inflates, runs preflate over the deflate, dumps inflated tar payloads (mostly text source) to solid where zstd-19 long-window-27 captures cross-file matches.
- **tar.tar.xz** — KIND_OPAQUE (no xz handler). Solid zstd-19 on already-xz'd bytes ties xz-9e on identical bytes ± noise.

## Concrete misses (in priority order, by impact-to-effort)

### 1. Small-input regression — FIXED 2026-05-05 (min-pack fallthrough)

Initial finding: `leftpad.tgz` (1.7 KB → 6.1 KB, +247%) and `is-odd.tgz` (2.8 KB → 7.0 KB, +144%) were the worst regressions in any bench to date. Mechanism: unwrapping a tightly-deflated 1.7 KB stream into 7 KB of inflated text and feeding to solid zstd-19 cannot beat the original gzip output (which is already near-optimal for those bytes), and we pay preflate reconstruction + recipe + solid framing overhead on top. Header overhead is small (1-byte input packs to 43 B), so this is a structural issue, not a fixed-cost floor.

Fix: `do_pack` now packs twice when at least one entry is unwrapped — once with container routing engaged (status quo), once with `force_opaque=1` — and keeps the smaller. After: `leftpad.tgz` → −1.09%, `is-odd.tgz` → −0.74%, `hello.deb` tightened from +0.04% to −0.04%. All M1–M3h synthetic headlines preserved byte-exactly. RT OK across both bench suites. Cost: 2× pack time on container-shaped inputs.

See `roadmap.md` §"min-pack fallthrough" for the diff summary.

### 2. zstd ladder cannot reproduce makepkg output (real coverage gap for KIND_ZSTD)

On `which.pkg.tar.zst`, manual probing of `(level, --long, --ultra)` combinations including `-22 --ultra --long=27`, `-19 --ultra --long=27`, `-20 --long=27`, etc., **none** reproduce the file byte-exact. Closest probe is 208 bytes off. Root cause: makepkg uses parameters outside our 7-entry ladder (likely related to `--auto-threads=physical` multi-threaded encoding, which produces output that single-threaded `zstd` can't reproduce regardless of level/window).

So KIND_ZSTD is currently a *synthetic-fixture-only* feature in practice. Real `.pkg.tar.zst` files all route to KIND_OPAQUE today.

Options:
- **Multi-threaded probe.** Add `-T<N>` to the ladder (probe `T1, T2, T4, T8`) — but this is non-deterministic across machines.
- **Wider ladder.** Extend to 20–30 entries covering more `(level, window, strategy)` combos with `--ultra`. Diminishing returns.
- **Frame-header heuristic.** Parse the zstd frame header in the input and try only the matching window/checksum settings, narrowing probe space dramatically.

The frame-header approach is the right answer; the other two are workarounds. None are in scope until we decide `.pkg.tar.zst` matters enough.

### 3. OP_XZ_STORE for ar entries (companion to KIND_XZ)

`hello.deb` is `ar(debian-binary, control.tar.xz, data.tar.xz)`. The ar walker is fine; the inner `.tar.xz` entries can't route format-aware because `OP_XZ_STORE` doesn't exist. With KIND_XZ + OP_XZ_STORE, the deb would inflate two layers of xz, route the inner ustar tar through `pack_tar`, and pick up format-aware wins on any media inside (likely small for `hello`, larger for media-heavy packages). The ladder/win shape will mirror M3f-ar's `.deb` headline (−13% vs xz-9e on the synthetic deb), assuming the inner-xz reproducibility story holds.

### 4. Github release zip headline is overhead-bound, not unwrap-bound

`release.zip` got 12 of 20 entries through preflate/redeflate but still ties xz-9e to within 759 bytes (−0.08%). Diagnosis is the same as the small-tarball case: a 965 KB ZIP is small enough that solid-mode bookkeeping eats most of the per-entry recompression benefit. The fix is the same min(unwrap, opaque) gate. Not a separate bug.

## What this changes in the roadmap

The "Next session" plan in `roadmap.md` originally ordered KIND_XZ next. The data said small-input fall-through was higher-impact, lower-effort, and should ship first — and it did (min-pack fallthrough, 2026-05-05). With that gone, the next two priorities are:

1. **Frame-header-driven zstd ladder** — converts an existing-but-broken kind (KIND_ZSTD) into a working one for real `.pkg.tar.zst` artifacts. Higher impact-per-LOC than KIND_XZ.
2. **KIND_XZ + OP_XZ_STORE** — still worthwhile for media-heavy `.tar.xz` and modern `.deb`, but the source-tarball headline will tie xz-9e (xz already optimal on source text). Value is correctness coverage, not headline.
